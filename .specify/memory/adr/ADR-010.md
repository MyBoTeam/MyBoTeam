## ADR-010: Agent Productivity Tools

### Status

**Accepted**

### Date

2026-06-24

### Owner

User/AI collaboration

### Sub-System

MCP & Tools

### Context

**Problem Statement:**
Agents need to produce tangible outputs beyond chat responses — scheduled recurring tasks, edited documents, and organized notes/todos. These capabilities transform agents from reactive chatbots to proactive productivity assistants.

**Forces:**
- Scheduling is the #1 most-requested feature for AI assistants — users want "set it and forget it"
- Document editing inline (not just reading) is table stakes for productivity agents
- Notes/todos with reminders compete with standalone apps — tight agent integration is the differentiator
- All three features must work offline (local-first)
- Scheduling must support natural language input — no cron expression knowledge required
- Document versioning must be robust enough for rollback
- Notes must be agent-accessible via tools (create, read, update, search, delete)

**References:**
- OpenClaw: Natural language cron scheduling with multiple schedule types
- Odysseus: Inline document editing with FIND/REPLACE, version history, suggestion mode
- Odysseus: Notes & Todos system with checklists, reminders, labels, categories
- Accomplish: Scheduler service with cron daemon
- PDR-008: Agent Productivity Tools

### Decision

**Decision:**
Three productivity features built as daemon services with agent-facing tools:

**Feature 1: Natural Language Scheduling**

**Schedule Types:**
- `at` — one-shot: ISO datetime (`2026-07-15T09:00:00`) or relative ("20m", "2h", "next monday")
- `every` — interval: "every 3 hours", "every morning at 9", "every weekday at 6pm"
- `cron` — 5-field cron expression (advanced, from NL parsing)

**Delivery Modes:**
- `chat` — result announced to the agent chat session
- `webhook` — POST payload to configured URL
- `session` — result saved to a specific agent session

**Management:**
- Full CRUD UI: list schedules (name, type, next run, status), edit, pause, remove
- Run history: last 50 executions per schedule with status, timestamps, output
- Scheduler runs as a daemon service using `node-cron` or equivalent in-process scheduler
- 50+ concurrent schedules supported without degradation

**Agent Tools:**
- `create_schedule(nl_description, type, delivery_mode)` — creates from natural language
- `list_schedules()` — returns active schedules
- `pause_schedule(id)` / `resume_schedule(id)`
- `delete_schedule(id)`
- `get_schedule_history(id)` — returns execution log

**Feature 2: Inline Document Editing**

**Operations:**
- `create(path, content)` — creates file with auto-detected language (by extension)
- `read(path, offset?, limit?)` — reads file with optional partial read
- `edit(path, oldString, newString, replaceAll?, dryRun?)` — FIND/REPLACE surgical editing:
  - `oldString` must match exactly one occurrence (uniqueness check) unless `replaceAll: true`
  - Fails atomically if `oldString` not found or not unique
  - Returns unified diff of changes
  - `dryRun: true` returns diff without applying
- `suggest(path, oldString, newString, reason)` — non-destructive suggestion mode:
  - Creates a suggestion object (stored in SQLite `doc_suggestions` table)
  - User can approve/deny via UI
  - Approved suggestions are applied as edits

**Version History:**
- Each edit creates a new version entry in `document_versions` table
- Version entry includes: `path`, `content` (or diff), `model` attribution, `summary` (LLM-generated), `timestamp`
- Rollback: restore any previous version by content

**Agent Tools:**
- `read_file(path, offset?, limit?)` — wrapped from File Tool Suite
- `edit_file(path, oldString, newString, replaceAll?)`
- `suggest_edit(path, oldString, newString, reason)`
- `list_versions(path)` — returns version history
- `rollback(path, versionId)` — restores previous version

**Feature 3: Notes & Todos**

**Note Model:**
- `type`: `text` (freeform) or `checklist` (with items)
- Fields: `title`, `content` (text) or `items[]` (checklist), `color`, `labels[]`, `pinned`, `archived`
- Checklist items: `{text, checked: boolean}`
- `dueDate`: triggers reminder
- `repeat`: `none | daily | weekly | monthly`

**Reminders:**
- Delivery channels: browser notification (primary), email (secondary, requires email config)
- Scheduled via the Scheduling system internally
- Agent tools can create/read/update/search/delete notes
- Full UI for viewing, searching, toggling, pinning, archiving

**Storage:**
- `notes` table in SQLite with JSON columns for flexible fields
- Full-text search on title + content via SQLite FTS5
- Labels stored in `note_labels` join table for filtering

**Agent Tools:**
- `create_note(title, content?, type?, color?, labels?, dueDate?, repeat?)`
- `list_notes(filter?)` — filter by label, pinned, archived, search query
- `update_note(id, fields)`
- `delete_note(id)`
- `toggle_todo(noteId, itemIndex)` — toggle checklist item
- `search_notes(query)` — FTS5 full-text search

### Consequences

#### Positive
- Scheduling moves agents from reactive to proactive — highest-value agent use case
- FIND/REPLACE editing is surgical and safe — no AI-generated corruption risk
- Suggestion mode enables user review before applying changes
- Notes system tightly integrated with agents (agents auto-create notes)
- All three work offline with full local storage
- Version history enables rollback of any document change

#### Negative
- Scheduling adds background process complexity (cron daemon, delivery guarantees)
- Document versioning increases storage requirements
- Notes system competes with established apps — needs clear agent integration value
- Suggestion mode adds UI surface area for review workflow

#### Risks
- Risk: Missed schedule executions — mitigated by retry logic, delivery confirmations, run history with alerts on >2 consecutive failures
- Risk: Document edit conflicts — mitigated by FIND/REPLACE uniqueness check that fails atomically on mismatch
- Risk: Notes become unused feature — mitigated by tight agent integration (agents auto-create notes from conversations)
- Risk: Scheduling NL parsing misses edge cases — mitigated by fallback to explicit cron expression editing in UI

### Common Alternatives

#### Option A: External services integration
**Description:** Integrate with Google Calendar, Apple Reminders, Google Docs instead of building native features.
**Trade-offs:** Leverages existing third-party services with established user bases; depends on third-party API availability, requires network connectivity for core features, and does not provide agent-native integration patterns.

#### Option B: Basic cron UI (no NL parsing)
**Description:** Provide a settings-page cron configuration UI instead of NL-based scheduling.
**Trade-offs:** Simpler to implement with explicit schedule configuration; requires users to understand cron expression syntax for schedule definition.
